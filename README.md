# TaskUp AI

Работающий локальный MVP для AI Sana: бизнес описывает потребность, уточняет детали,
подтверждает карточку и публикует задачу; команды предлагают решения, бизнес выбирает
одну или несколько команд и подтверждает выполненный прототип.

## Быстрый запуск

Требуются Python **3.11+**, Node.js **22.12+** (или 24 LTS) и npm.
Проверенная среда разработки: Windows, Python 3.14.3, Node.js 24.14.0, npm 11.9.0.
Интернет нужен для первой установки зависимостей. После установки локальный сценарий
работает без интернета, платного ключа и внешних сервисов. Оба сервера привязываются к loopback.

### Windows PowerShell

В корне проекта, первый терминал:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
Copy-Item backend/.env.example backend/.env
Set-Location backend
..\.venv\Scripts\python.exe -m app.seed
..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Второй терминал, начиная с корня проекта:

```powershell
Set-Location frontend
npm.cmd ci
npm.cmd run dev
```

Откройте **http://127.0.0.1:5173**. API: http://127.0.0.1:8000/api/health,
интерактивная документация: http://127.0.0.1:8000/docs.
Копирование `.env` нужно только при первой установке; не перезаписывайте свою конфигурацию.
Активация виртуального окружения не требуется, поэтому политика выполнения PowerShell не мешает.

### macOS / Linux

Первый терминал, из корня:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements.txt
cp backend/.env.example backend/.env
cd backend
../.venv/bin/python -m app.seed
../.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Второй терминал, из корня:

```bash
cd frontend
npm ci
npm run dev
```

Команды для macOS/Linux подготовлены, но в этой сессии выполнялись проверки на Windows.

## Архитектура и файлы

Модульный монолит: React 19 + TypeScript + React Router + Vite + Tailwind CSS →
FastAPI + Pydantic → SQLAlchemy → SQLite. Внешний LLM вызывается только из backend.
Frontend использует настоящий API; localStorage хранит исключительно выбранный демо-профиль.

```text
backend/app/api/             маршруты, права и сериализация
backend/app/models.py       Business, Task, Team, Proposal, Milestone
backend/app/schemas.py      карточка, ответы, предложения, AI-схемы
backend/app/services/       детерминированный рейтинг
backend/app/services/ai/    интерфейс, HTTP-адаптер, fallback, проверка evidence
backend/prompts/            два системных промпта
backend/app/seed.py         идемпотентный seed и явный reset
backend/data/               локальная SQLite, исключена из исходников
backend/tests/              проверки правил и сквозной API-сценарий
frontend/src/api/           HTTP-клиент и состояния запросов
frontend/src/types/         общий с Pydantic TaskCard
frontend/src/pages/         каталог, кабинеты, конструктор, карточка
frontend/src/components/    рейтинг, поля критериев и общие состояния
frontend/tests/             браузерный сценарий Playwright
seed/                      JSON-наборы синтетических данных
```

[API_CONTRACT.md](API_CONTRACT.md) содержит маршруты и примеры payload.
[Подробная архитектура](docs/ARCHITECTURE.md) объясняет состав проекта, движение данных и причины основных решений.
[DEMO_SCRIPT.md](DEMO_SCRIPT.md) — сценарий до пяти минут с подготовленными ответами.
[TEAM_PLAN.md](TEAM_PLAN.md) — разделение работы для трёх участников.

Версии backend, включая транзитивные зависимости, зафиксированы в `requirements.txt`.
Frontend имеет точные версии в `package.json` и `package-lock.json`; используйте `npm ci`.

## База и тестовые данные

При старте создаются только отсутствующие таблицы. Данные не очищаются и не заменяются.
По умолчанию файл — `backend/data/taskup.db`; повторный запуск серверов сохраняет работу.
Seed запускается отдельно из `backend`: `python -m app.seed` (Python из `.venv`).
Повторный seed не создаёт дубликаты и не перезаписывает существующие записи.

Seed включает 3 бизнеса, 5 описаний, 5 карточек со всеми ключами, 5 команд и 5 предложений.
Два предложения относятся к одной задаче. Баллы **100, 85, 65, 20, 45** получены общей
функцией рейтинга, а не записаны как декоративные значения. В каталоге есть все четыре уровня.
Имена, контакты и адреса вымышлены. `example.org` — явно отмеченная демонстрационная ссылка,
а не заявление о существующем прототипе.

Явный сброс **всей работы в настроенной демо-БД** с повторным seed:

```powershell
# Из backend; используйте только когда намеренно хотите начать демо заново.
..\.venv\Scripts\python.exe -m app.seed --reset --yes
```

На macOS/Linux замените Python на `../.venv/bin/python`.
Тесты backend используют изолированную БД. Каждый браузерный запуск создаёт отдельный
`backend/data/e2e-<timestamp>.db`, рабочую базу не сбрасывает.

## Карточка, подтверждение и каталог

- `draft_card` — редактируемый вариант. AI и сохранение меняют только его.
- `confirmed_card` — снимок после явного действия человека. Вместе с ним одной
  транзакцией сохраняются рейтинг, расшифровка и подтверждённая отрасль.
- `is_published` — отдельный признак публикации. До первого подтверждения публичного доступа нет.

Редактирование опубликованной задачи оставляет в каталоге последний подтверждённый снимок.
Кнопка «Подтвердить сведения» обновляет этот снимок и его место в каталоге. До нажатия
показывается **«Будет после подтверждения»**. Удаление информации может снизить оценку.
Версия задачи проверяется и в запросе, и в SQL UPDATE; устаревший редактор получает 409.

Публикация требует подтверждения текущей карточки и содержательного названия.
Нет минимального рейтинга: **«Черновик» 0–39 — уровень готовности, а не запрет публикации**.
Низкорейтинговые задачи видны всем и принимают предложения. Каталог сортируется по баллам
вниз, при равенстве — по времени публикации вверх, затем по ID вверх. Есть фильтры по теме
и готовности и сортировка по новым публикациям.

## Прозрачный рейтинг

| Подпункт | Баллы |
|---|---:|
| Контекст + потребность | 10 + 10 |
| Данные + источник | 10 + 10 |
| Ожидаемый результат | 15 |
| Хотя бы один полный критерий: условие, ожидаемое значение и проверка | 15 |
| Срок + ограничения | 5 + 5 |
| Пользователи | 10 |
| Контакт | 5 |
| Формат взаимодействия **и** обратная связь | 5 |

Сумма: 100. Уровни: 0–39 «Черновик», 40–69 «Рабочая», 70–89 «Готовая»,
90–100 «Приоритетная». Каждый подпункт содержит основание, недостающие поля и возможный
прирост. UI показывает расстояние до следующего уровня и изменение после подтверждения.

Пустые значения и заглушки вроде `не знаю`, `TBD`, `не указано`, `потом` не начисляют баллы.
`данных нет` не означает наличие материалов. Явное человеческое «жёсткого срока нет»
допустимо. Длина текста, число откликов, известность бизнеса и ответ LLM не участвуют.
Это **проверка заполненности по рубрике, а не истинности или качества бизнес-сведений**.

## Предложения и результаты

Команда отправляет идею, план, срок и необязательный http/https URL.
Один профиль может отправить одно предложение на задачу; общего лимита команд нет.
Владелец задачи вручную принимает/отклоняет каждое предложение. Принятие одного не
меняет остальные, можно выбрать несколько команд или отклонить все.

Выбранная команда отправляет один этап `prototype`. Только владелец задачи подтверждает
результат. После отправки этапа смена решения по предложению блокируется, чтобы не отзывать
выполняемую работу. За подтверждённый прототип начисляется +10; повторное подтверждение
возвращает те же 10, а не добавляет новые. Общий результат команды — сумма подтверждённых
этапов. Отправка предложения, выбор команды и ожидание проверки дают 0 баллов.
Рейтинг задачи от этого не меняется.

## Настройки

Backend читает `backend/.env`; значения окружения имеют приоритет.

| Переменная | Значение / назначение |
|---|---|
| DATABASE_URL | `sqlite:///./data/taskup.db` при запуске из backend; без .env — абсолютный путь внутри backend/data |
| CORS_ORIGINS | `http://localhost:5173,http://127.0.0.1:5173`, только явные локальные origins |
| DEMO_MODE | `true`; false отключает демо-профили и все приватные действия |
| LLM_PROVIDER | `rule_based` по умолчанию; `openai_compatible` включает внешний адаптер |
| LLM_API_KEY | секрет провайдера, только backend |
| LLM_BASE_URL | `https://api.openai.com/v1`, адаптер добавляет `/chat/completions` |
| LLM_MODEL | точный ID доступной вам модели; по умолчанию пусто |
| LLM_TIMEOUT_SECONDS | 20, допустимо 0 < значение ≤ 120 |
| VITE_API_URL | frontend/.env: `http://127.0.0.1:8000` по умолчанию |

Чтобы использовать внешний AI, самостоятельно задайте ключ, модель и
`LLM_PROVIDER=openai_compatible`, затем перезапустите backend. Frontend не получает ключ.
Платные API в ходе разработки не вызывались. Публичный деплой не выполнялся.

## AI: вход, выход и ошибки

Адаптер реализует реальный HTTP POST Chat Completions: bearer-ключ, `model`, системный
и пользовательский `messages`, `response_format: {type: "json_object"}`, `store: false`.
JSON mode не гарантирует соответствие схеме, поэтому ответ отдельно проверяется Pydantic.
Сверено с официальными страницами [Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)
и [Structured outputs](https://developers.openai.com/api/docs/guides/structured-outputs).
Другие совместимые провайдеры должны поддерживать эти параметры; несовместимость приводит к fallback.

Интерфейс `AIProvider` содержит `analyze_draft` и `compose_card`.
Анализ учитывает отрасль и ответы, возвращает 3–5 вопросов с ID `q_<field>`.
Составление получает только исходный текст и ответы. Нет скрытого дополнения фактами профиля.
Прямые ответы и строки с явными метками копируются; простые фразы «Мы…», «Хотим…»
распознаются консервативно. Нераспознанный текст остаётся исходным описанием для человека.

Пример фактически выполненного локального вызова:

```json
{
  "description": "Мы учебный центр. Хотим навести порядок с оплатами.",
  "answers": [
    {"question_id":"q_users","field":"users","value":"Два администратора"},
    {"question_id":"q_data","field":"data","value":"Пока не знаю"}
  ]
}
```

Существенная часть результата:

```json
{
  "mode": "rule_based",
  "card": {
    "context": "Мы учебный центр.",
    "need": "Хотим навести порядок с оплатами.",
    "users": "Два администратора",
    "data": null,
    "deadline": null,
    "contact": null,
    "success_criteria": []
  },
  "evidence": {
    "users": [{"source_id":"answer:q_users","quote":"Два администратора"}]
  }
}
```

Полный вход/выход сохранён в [docs/AI_EXAMPLE.json](docs/AI_EXAMPLE.json).
Промпты: [анализ](backend/prompts/analyze_task.txt), [карточка](backend/prompts/compose_card.txt).
Они отделяют данные от инструкций, запрещают выдумки, публикацию, выбор команд и использование
персональных или чувствительных признаков. Неожиданные ключи (`score`, `confirmed`,
`selected_team_id`) отвергаются. Для каждого непустого фактического поля нужны источник
и точная цитата. У критериев проверяется каждый лист отдельно. Поля без цитаты удаляются.
Наличие цитаты **не доказывает правильную интерпретацию**: финальная проверка принадлежит человеку.

Нет ключа/модели, timeout, HTTP-ошибка, отказ, обрезанный ответ, malformed JSON или неверная
схема → локальный `RuleBasedFallback` и понятное безопасное сообщение с `mode: rule_based`.
Тексты исключений, ответ с ключом и внутренности провайдера не выдаются клиенту.
Например, ответ `{"card":{"score":100},"evidence":{}}` не проходит схему и заменяется
локальным результатом. Эти ветки, включая успешный контракт HTTP, проверяются с mock-ответами;
**живой внешний LLM не проверен**.

## Проверки

Windows, из корня проекта:

```powershell
Set-Location backend
..\.venv\Scripts\python.exe -m pytest
Set-Location ../frontend
npm.cmd run typecheck
npm.cmd run build
npm.cmd run test:e2e
```

macOS/Linux: Python `../.venv/bin/python`, команды `npm run …`.
Браузерные тесты используют установленный **Google Chrome** в headless-режиме.
Можно выбрать Edge: `$env:PLAYWRIGHT_CHANNEL='msedge'` в PowerShell или
`PLAYWRIGHT_CHANNEL=msedge npm run test:e2e` в shell. Свободные порты: 8011 и 5174.
Playwright сам запускает и останавливает тестовые backend/frontend; `.venv` должна быть
в корне. Скриншоты сохраняются в `frontend/test-results/` и не входят в исходники.

Фактические результаты и замечания среды записаны в [VERIFICATION.md](VERIFICATION.md).

## Ограничения MVP

Демо-заголовки `X-Demo-Role` / `X-Demo-Actor-Id` имитируют вход и легко подменяются.
Backend проверяет существование профиля, его роль и владельца ресурса, однако это
**не безопасная аутентификация**. Приложение предназначено только для локальной демонстрации
на синтетических данных. Не размещайте здесь реальные контакты, персональные данные и секреты.

Нет регистрации, чата, уведомлений, загрузки файлов и производственной инфраструктуры.
Один демонстрационный этап на предложение. История всех ревизий карточки не хранится —
только текущий черновик и последний подтверждённый снимок. Миграций схемы нет: для новой
несовместимой схемы потребуется отдельная БД или явная миграция. Отправленные ссылки
не скачиваются сервером; HTML выводится как текст. UI рассчитан прежде всего на desktop.
