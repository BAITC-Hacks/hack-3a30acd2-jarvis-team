# Демонстрация AI Sana Challenge Hub — 3–5 минут

## Подготовка

Запустите приложение по [README.md](README.md) с пустым `OPENAI_API_KEY`. Для готовых демоаккаунтов отдельно выполните `npm run db:seed`. Seed обновляет первоначальные примеры и сбрасывает их статусы: не запускайте его во время показа. Можно обойтись без seed, зарегистрировав собственные аккаунты бизнеса и команды.

Откройте **http://127.0.0.1:3000** в двух браузерных профилях с раздельными cookie. Подойдут обычное и приватное окно.

| Окно | Email | Пароль |
| --- | --- | --- |
| Бизнес | `business@demo.local` | `SanaDemo2026!` |
| Команда Vector | `team@demo.local` | `SanaDemo2026!` |

На странице входа нажмите **«Демо: бизнес»** или **«Демо: команда»**, затем **«Войти»**. Кнопки заполняют данные, но не входят автоматически.

Пример ниже вымышленный. Над вопросами будет показан **«Демонстрационный режим»**: вопросы подбирает локальный сценарий, внешний ИИ не используется. Для показа с настоящей моделью настройте ключ заранее и учитывайте время ответа.

## 1. Главная и создание задачи

Покажите главную: короткое объяснение, три шага и каталог с поиском. На компьютере навигация находится сверху, на телефоне — в кнопке меню.

> «Бизнес описывает проблему обычными словами. Мы помогаем уточнить детали, чтобы команда поняла, что нужно сделать».

В окне бизнеса нажмите **«Создать задачу»**. Введите компанию **«Цветочная мастерская · демо»**, выберите отрасль **«Логистика»** и вставьте:

> У нас небольшая служба доставки цветов. Диспетчер распределяет заказы вручную, и курьеры часто опаздывают. Хотим лучше планировать маршруты, но не понимаем, с чего начать.

Этот же текст можно вставить кнопкой **«Вставить пример про доставку»**. Нажмите **«Продолжить»**: черновик сохранится, откроется второй шаг.

## 2. Вопросы по одному

Покажите, что на экране только один вопрос и один ответ, а сверху — «Вопрос 1 из …».

> «Не нужно заполнять большую анкету сразу. Отвечаем на один вопрос и идём дальше. Если чего-то пока не знаем, это можно пропустить».

Выбирайте ответ по смыслу вопроса из таблицы ниже. После каждого ответа нажимайте **«Далее»**, после последнего — **«Собрать описание»**. Для возвращения есть **«Назад»**, для неизвестного — **«Пока не знаю — пропустить»**.

| О чём спрашивают | Готовый ответ |
| --- | --- |
| Название | Планировщик доставки цветов — демо |
| Проблема | Диспетчер вручную распределяет заказы. Перед праздниками курьеры не успевают доставлять цветы вовремя. |
| Нужное решение | Веб-прототип планировщика маршрутов для диспетчера с предупреждением об опозданиях. |
| Что передаст команда | Работающий прототип, исходный код, отчёт о проверке и инструкция для диспетчера. |
| Как оценить результат | Снизить долю опозданий с 25% до 10% за месяц пилота по сравнению с прошлым месяцем. Проверять по журналу доставок. |
| Данные | Есть история заказов, маршрутов и времени доставки за 3 месяца в Excel. Диспетчер предоставит команде обезличенную выгрузку CSV без имён и телефонов клиентов. |
| Ограничения | Только бесплатные инструменты. Не передавать персональные данные сторонним сервисам. Прототип должен работать в браузере. |
| Срок | 6 недель после выбора команды, первая демонстрация через 2 недели. |
| Навыки | Python, SQL, React. |
| Пользователи | Диспетчер и курьеры цветочной доставки. |
| Как работают сейчас | Заказы ведём в Excel, маршруты составляем вручную перед каждой сменой. |

Вопросов будет до пяти; остальные сведения можно добавить на следующем шаге.

## 3. Проверка и публикация

На экране **«Проверьте описание задачи»** сразу видны четыре обязательных поля:

- **«Название задачи»**;
- **«Что нужно решить?»**;
- **«Какое решение вы хотите получить?»**;
- **«Что команда должна передать вам?»**.

Проверьте их и при необходимости вставьте подходящие ответы из таблицы. Ниже, в **«Детали для команды»**, дополните показатель успеха, данные, ограничения, срок и навыки. Для сравнения раскройте **«Сравнить с исходным описанием»**.

> «Всё можно исправить прямо здесь. Если чего-то не хватает, сайт назовёт конкретное поле и поможет перейти к нему».

В блоке **«Насколько понятна задача»** можно раскрыть **«Из чего складывается оценка»**. Объясните, что баллы отражают полноту описания, а не обещают успех проекта. Для публикации нужны четыре обязательных поля и не менее 60 баллов.

Нажмите **«Сохранить»** или дождитесь **«Сохранено»**. При желании перезагрузите страницу: ответы и ручные изменения останутся на месте. Когда появится **«Можно публиковать»**, нажмите **«Опубликовать задачу»**.

Покажите сообщение: **«Задача опубликована. Теперь команды могут отправить отклик.»**

## 4. Отклик команды

В окне команды откройте **«Каталог задач»**, найдите задачу по названию **«Планировщик доставки цветов — демо»** и откройте карточку. Нажмите **«Откликнуться»** — страница перейдёт к форме.

Вставьте:

- **Предложение решения:** «Проверим историю заказов, подготовим алгоритм распределения доставок и создадим веб-прототип для диспетчера. Сравним предложенные маршруты с текущими».
- **Опыт вашей команды:** «Делали учебные проекты на Python и SQL, создавали интерфейсы на React и работали с картами».
- **Предполагаемый срок:** «6 недель, первая демонстрация через 2 недели».

Нажмите **«Отправить отклик»**. Покажите сообщение об отправке и статус **«На рассмотрении»**. Профиль команды прикладывается автоматически.

## 5. Выбор команды

Вернитесь в окно бизнеса, обновите страницу задачи и нажмите **«Отклики команд: 1»**. Откройте предложение Vector и нажмите **«Выбрать команду»**.

В окне команды перейдите в **«Моя команда»** → **«Мои отклики»**. У задачи появится статус **«Выбрана»**. В разделе бизнеса **«Мои задачи»** она получит статус **«Команда выбрана»**.

> «Из короткого описания получилась понятная задача: что сделать, как проверить результат и что передать бизнесу. Команда отправила предложение, а бизнес выбрал исполнителя».

Для повторного показа создайте новую задачу и добавьте к названию уникальное слово. После выбора команды новые отклики не принимаются.

## Дополнительная проверка сохранения

Эту часть удобно показать отдельно от короткого выступления.

1. Откройте новый черновик на шаге проверки. Измените название и сразу нажмите **«Мои задачи»**. Переход дождётся сохранения; после возвращения новый текст останется. Та же защита действует при нажатии **«Выйти»**.
2. Откройте тот же черновик в двух вкладках. Во второй измените название и дождитесь **«Сохранено»**.
3. В первой введите другое название и нажмите **«Сохранить»**. Появится **«Задача уже изменилась»**: сервер отклоняет устаревшую версию с HTTP 409 и не затирает изменения второй вкладки.
4. В первой вкладке нажмите **«Сохранить отдельным черновиком»**. Ваш текст сохранится в новой задаче; исходная сохранит название из второй вкладки.

Не закрывайте вкладку с конфликтом до сохранения отдельного черновика: локальные правки остаются в её полях, пока вы не сохраните копию.
